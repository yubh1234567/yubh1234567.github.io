GitHub Pages의 개념

GitHub Pages는 저장소에 있는 정적 파일을 웹사이트로 공개하는 호스팅 서비스다. HTML은 페이지의 구조, CSS는 디자인, JavaScript는 검색이나 필터 같은 상호작용을 맡는다. 서버에서 실행되는 PHP나 Python이 없어도 개인 블로그와 포트폴리오를 운영할 수 있다.

사용자 사이트와 프로젝트 사이트의 차이

GitHub Pages의 주소는 저장소를 구성하는 방식에 따라 두 가지로 나뉜다.

사용자 사이트

저장소 이름을 본인아이디.github.io로 지정하는 방식이다. 완성된 주소는 https://본인아이디.github.io가 된다. 계정마다 하나의 대표 사이트를 만들 수 있어 개인 블로그에 잘 맞는다.

프로젝트 사이트

일반 저장소에서 Pages를 활성화하는 방식이다. 주소는 https://본인아이디.github.io/저장소이름/ 형태다. 프로젝트 문서나 결과물 시연에 적합하다.

블로그의 파일 구성

프레임워크나 배포용 테마 없이 HTML, CSS, JavaScript로 구성했다. 빌드 과정 없이 파일을 올리면 바로 배포할 수 있고, 화면의 각 요소도 직접 조정할 수 있는 구조다.

PROJECT TREELOCAL
.
├── index.html          # 메인 페이지
├── styles.css          # 공통 디자인
├── script.js           # 검색·카테고리 필터
├── post.css            # 글 페이지 디자인
├── post.js             # 읽기 진행률
├── posts/              # 기술 기록
├── assets/             # 아이콘과 이미지
└── .nojekyll           # Jekyll 처리 비활성화

처음 정한 여섯 분야는 다음과 같다.

  • CTF / Wargame

  • 블로그 / 기술문서
  • 논문 / 컨퍼런스
  • 공모전 / 자격증

GitHub Pages 배포 절차

  1. GitHub 계정에 본인아이디.github.io라는 Public 저장소 생성.
  2. 완성한 블로그 파일을 저장소의 main 브랜치에 업로드.
  3. 저장소의 Settings → Pages 메뉴로 이동.
  4. Source 항목에서 Deploy from a branch 선택.
  5. main 브랜치와 /(root) 폴더를 선택한 뒤 저장.
  6. 배포 완료 후 Pages 화면의 Visit site에서 결과 확인.
PUBLIC CHECK

Public 저장소와 Pages 사이트에 비밀번호, API 키, 개인정보를 넣지 않는 것이 기본 원칙.

세부 기준은 GitHub Pages 공식 소개와 배포 소스 설정 문서에서 확인했다.

첫 구축 이후의 과제

첫 블로그를 만들며 확인한 핵심은 기록을 계속 추가할 수 있는 구조였다. 카테고리를 먼저 정하고 글 데이터를 한곳에서 관리하니 새 글을 올릴 때 사이트 전체를 고칠 필요가 줄었다.

다음 과제는 각 분야에 실제 학습 기록을 채우는 일이다. 해결 결과만 적지 않고 환경, 실패한 시도, 판단 근거를 함께 남겨 재현 가능한 아카이브로 확장할 계획이다.
