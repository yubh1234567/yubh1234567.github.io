GitHub Pages란?

GitHub Pages는 GitHub 저장소에 있는 정적 파일을 웹사이트로 공개하는 호스팅 서비스다. HTML은 페이지의 구조, CSS는 디자인, JavaScript는 검색이나 필터 같은 상호작용을 담당한다. 서버에서 실행되는 PHP나 Python 없이도 개인 블로그와 포트폴리오를 운영할 수 있다.

한 줄 정리

로컬 파일을 수정 → GitHub 저장소에 반영 → Pages가 사이트로 배포하는 흐름이다.

사용자 사이트와 프로젝트 사이트

GitHub Pages 주소는 저장소를 구성하는 방식에 따라 두 가지로 나뉜다.

사용자 사이트

저장소 이름을 정확히 본인아이디.github.io로 만든다. 완성된 주소는 https://본인아이디.github.io가 된다. 계정당 하나의 대표 사이트를 만들 수 있어 개인 블로그에 잘 맞는다.

프로젝트 사이트

일반 저장소에서 Pages를 활성화하는 방식이다. 주소는 https://본인아이디.github.io/저장소이름/ 형태가 된다. 프로젝트 문서나 데모에 적합하다.

이번 블로그의 구성

이번 미션에서는 프레임워크나 테마를 그대로 사용하지 않고 HTML, CSS, JavaScript로 직접 구성했다. 덕분에 빌드 과정 없이 파일을 올리는 것만으로 배포할 수 있고, 각 요소를 원하는 방식으로 수정할 수 있다.

PROJECT TREE
.
├── index.html          # 메인 페이지
├── styles.css          # 공통 디자인
├── script.js           # 검색·카테고리 필터
├── post.css            # 글 페이지 디자인
├── post.js             # 읽기 진행률
├── posts/              # 작성한 기술 글
├── assets/             # 아이콘과 이미지
└── .nojekyll           # Jekyll 처리 비활성화

미션 요구사항에 맞춰 다음 여섯 카테고리를 메뉴에 구성했다.

  • 개발
  • CTF / Wargame
  • Bug Bounty
  • 블로그 / 기술문서
  • 논문 / 컨퍼런스
  • 공모전 / 자격증

배포 순서

  1. 본인 GitHub 계정에서 본인아이디.github.io라는 Public 저장소를 만든다.
  2. 완성한 블로그 파일을 저장소의 main 브랜치에 올린다.
  3. 저장소의 Settings → Pages로 이동한다.
  4. Source는 Deploy from a branch를 선택한다.
  5. 브랜치는 main, 폴더는 /(root)를 선택한 뒤 저장한다.
  6. 배포가 끝나면 Pages 화면의 Visit site로 결과를 확인한다.
공개 전 확인

공개 저장소와 Pages 사이트에는 비밀번호, API 키, 개인정보 같은 민감한 내용을 절대 넣지 않는다.

자세한 기준은 GitHub Pages 공식 소개와 배포 소스 설정 문서에서 확인했다.

회고와 다음 단계

첫 블로그를 만들며 가장 크게 배운 점은 디자인보다 기록을 이어갈 수 있는 구조가 중요하다는 것이다. 카테고리를 먼저 만들고 글 데이터를 한곳에서 관리하도록 구성하니, 새 글을 추가할 때 사이트 전체를 고칠 필요가 줄었다.

다음 단계는 각 카테고리에 실제 학습 기록을 하나씩 채우는 것이다. 문제를 해결한 결과뿐 아니라 환경, 실패한 시도, 해결 근거를 함께 기록해 재현 가능한 아카이브로 발전시킬 예정이다.
